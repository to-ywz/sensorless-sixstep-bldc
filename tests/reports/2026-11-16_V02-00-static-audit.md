## 2. 保护链逐段结论

| 环节 | 静态依据与结论 | 当前固件实际状态 |
|---|---|---|
| 模拟CMP1 → RAW | RAW是模拟比较器原始输出；CMP_DATA bit1可读。读到RAW不等于FAIL路径已使能（M-CMP） | 应用/platform/board/bench未发现CMP1初始化或CMP/DAC配置调用；SDK提供函数不代表已使用 |
| RAW → CMP_BLCWIN | RAW绕过CMP数字接口滤波，但送MCPWM的路径仍受PWM窗口门控（M-CMP 184、195–196） | 未发现应用写CMP_BLCWIN或窗口极性；不可假定启动状态满足保护要求 |
| 开窗极性 | 选中CHnP的条件下，W_PWM_POL=1允许高电平窗口，=0允许低电平窗口；窗口外比较信号为0。这是电平门控，**不是固定时间LEB**（191–196） | S-CMP把CMP1.W_PWM_POL写CFG bit7，把CH0P–CH3P窗口使能写BLCWIN[7:4]；尚无产品配置 |
| 窗口 → FAIL1 | FAIL012[11:10]=1选择CMP1 RAW；bit5使能FAIL1。保护CH0/1/2，无需CMP1_OUT→BKIN飞线（M-PWM表14-48） | StructInit清零后未覆盖FAIL1选择/使能，故为SEL=0、EN=0；硬件CMP保护尚未启用 |
| FAIL极性/滤波 | FAIL1_POL bit3：0高有效，1反相后即低有效；不应把CMP数字IRQ极性当FAIL极性（M-CMP 184，M-PWM 1675） | 默认POL=0但输入禁用，不能称作已配置保护。窗口外0与低有效FAIL组合可能制造窗口外故障，须单独验证 |
| FAIL → MOE | EIF.FAIL1_IF/FAIL0_IF置位会清FAIL012.MOE，响应不依赖CPU先执行STOP（M-PWM 1672、1679） | 有软件MOE关断/启动，尚无CMP故障注入证据 |
| MOE + CH_MSK → CH_DEF | CHx_FAIL_EN=1才在FAIL或MOE=0时强制默认态；为0会继续内部输出，不能只看MOE。默认态绕过通道反相/交换（1753–1793） | F-OFF已设置CH0/1/2六路响应使能和P=0/N=1；对应低6位CH_DEF=0x15、CH_MASK=0x3F（只描述低6位）。手册CH_MSK/CH_MASK与SDK宏MCPWM0_CH_MASK指同一0x40010CBC |

## 3. FAIL滤波时钟与16周期

M-PWM的Filter说明及FLT/TCLK表给出：一级分频编码c=CLK_DIV[1:0]，实际系数为2^c（1/2/4/8）；二级d=FLT_CLKDIV[7:0]，实际系数d+1（1…256）。因此在工作时钟有效的前提下：

`f_filter = f_MCLK / (2^c × (d+1))`

`T_filter_nominal = 16 × 2^c × (d+1) / f_MCLK`

**c=0不是乘0；d=0不是旁路滤波。** 文本要求稳定超过16个滤波周期，边界相位/同步开销待测；此公式只表达名义滤波宽度，不能作为CMP到pad/Gate的总延迟或保证上界。

当前A4/A5：StructInit清零、CLK_DIV=0，未覆盖IO_CMP_FLT_CLKDIV，因此MCPWM_Init写FLT=0。48MHz RC的名义示例为16/48MHz≈0.333µs；96MHz仅为另一个计算示例≈0.167µs，**不是当前板实测时钟**。CLK_DIV=0、FLT=12时48MHz示例约4.333µs；SDK注释区示例参数不属于当前运行配置。

时钟必须分开检查：

1. M-CLK表6-5与S-SYS一致：`SYS_CLK_FEN[10]`是MCPWM0工作门控，`[2]`是CMP数字模块门控；`MCPWM_Init()`显式使能MCPWM0。
2. `cfg.MCLK_EN`实际写`MCPWM0_TCLK[2]`（手册名CLK_EN），不能与SYS_CLK_FEN混为一位；BASE_CNT0_EN bit6只控制计数器运行，不证明滤波时钟已开。
3. 模拟CMP1使能在SYS_AFE_REG5 bit7；S-CMP的CMP_Cmd同时处理模拟模块与CMP数字模块门控。应用尚未调用，不得从SDK函数存在推断硬件已开。
4. **资料冲突：** M-PWM 107行写MCLK/FCLK[4]，但M-CLK与SDK将bit4分给TIMER0、MCPWM0为bit10。不能据此去打开TIMER0“修复保护”，也不把FCLK[4]自行解释成SYS_CLK_FEN[4]。需要原版时钟图/勘误确认该编号含义。
5. 寄存器可访问不证明工作时钟有效（M-CLK表后注释）。停止计数、停模块时钟、CPU HALT/STOP是不同条件；本轮无硬件验证，首轮不以断点停核或关时钟做故障实验。

## 4. TR0_AEC、CNT0与CBC边界

- M-PWM 1679明确：FAIL0/1关断CH0/1/2，**CNT0继续正常运行**。不是FAIL触发后CNT0停止、清零或自动重启。FCNT可在FAIL_0CAP=1时捕获计数值，但应用尚未启用捕获。
- 计数周期是从−TH0到+TH0后回−TH0，名义(2×TH0+1)个计数时钟；T0是回卷边界、T1是零点。零点不是自然等于完整PWM周期边界。
- SDCFG.TR0_AEC bit6是**更新事件**自动清EIF[5:4]并置MOE，恢复CH0/1/2；不是比较器下降沿恢复，也不是CNT0复位位。更新源/间隔与T0/T1更新使能分别核对。
- 当前F-PWM禁用AEC、T0自动更新，AUEN=0；换相apply会软件暂停CNT0、写−PERIOD并手动UPDATE后再开CNT0/MOE。这是软件重装相位，不是FAIL的硬件动作，也不是CBC实现。
- AEC=0只禁硬件自动清除/恢复；**不能保证软件RUN不重新写MOE**。当前A4/A5启动函数会置MOE，没有CMP故障锁存状态机，不可当作已实现LATCH-01。
- 手动UPDATE是否参与AEC、持续FAIL与自动置MOE的优先关系、关窗导致FAIL撤销后是否同周期重开、更新间隔如何对应完整周期，均须原图/隔离时序确认；不能只置AEC=1便宣布CBC完成。
