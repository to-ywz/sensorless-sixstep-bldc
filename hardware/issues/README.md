# Hardware Issues

记录当前硬件上已经观察到、但未必需要立即解决的问题。

## 问题处理深度

采用“先记录、后关联、再决定是否整改”，避免把每个小现象都扩展成独立的设计任务。

1. **记录层**：记录现象、位置、条件、数据和不确定性。小问题先停留在这一层。
2. **关联层**：出现新的相关现象时，通过 Related Issues 将证据串联起来，再统一判断是否存在共同原因。
3. **整改层**：只有当问题影响功能、安全边界、可靠性，或多项证据指向同一设计缺陷时，才制定验证计划和硬件/软件整改。

分析假设不是根因；候选方案不是整改结论。不要仅凭单次波形就冻结 RC 参数、串联电阻值或 PCB 改版要求。

## 状态定义

- **RECORD ONLY**：保留观察结果，暂不投入专项排查。
- **OPEN**：已达到需要进一步调查的条件。
- **DEFERRED**：因当前硬件/进度限制暂缓；不代表风险已消除。
- **MITIGATED**：已有措施降低影响，但尚未完整关闭。
- **CLOSED**：原因和措施已验证，并在目标硬件版本完成验收。
